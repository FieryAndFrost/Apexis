# 参数调整通信优化（2026-09-16）

## 改动

- WRITE 仍然只写变化字段；继续校验事务回执、revision，并等待完整通知和 ACK。没有把请求值直接当作设备实际值。
- 描述读取从 WRITE 的忙碌周期中移出。设备数值确认后即可恢复编辑，不必等全部显示文字查询结束。
- 当前 UNIT 的名称、范围、可见数和标签能力按会话、音色、UNIT、TYPE、model_ref、规范参数数缓存。普通参数变化只查变化项的 GET21；GET21 返回 error6 后，在该缓存有效期内直接显示设备实际整数。
- 普通变化不再增加控件 metadataGeneration，不销毁重建整组旋钮；全局音量、旁路、其他 UNIT 的参数变化不重查当前 UNIT 的描述。
- Mode/Sync、TYPE、模型变化及重新同步/连接使相关缓存失效。未读取新范围前不展示旧参数控件。读取中的过期结果不会覆盖新选择或新设备值。
- 旋钮和滑条支持异步提交，等待时显示草稿及省略号；收到完成结果后切回设备实际值，包括设备规范化后的不同值或失败时的原值。草稿不写入设备镜像。
- 保留松手提交及严格串行业务请求；没有引入拖动写入队列或固定延时。

## 固件兼容边界

范围/可见数依赖优化仅对演示设备与已核对源码的 GT1 0.2.124 启用。
依据 `apps/effects/effect_registry.c` 的 `parameter_for_values`、
`display_parameter_count`、`format_parameter` 及效果 schema，Mode/Sync 是当前固件的动态描述依赖。
未知固件版本在参数变化时仍完整重读，不凭 TYPE 编号猜测范围。
新增固件依赖或改动参数名称时必须重新审核后扩展版本策略。

## 验证与限制

`test/parameter_refresh_test.dart` 覆盖请求数、error6 缓存、Mode/Sync、模型、外部修改、切换 UNIT、隐藏页、重连和过期回复。
8 参数效果在缓存有效时，普通单参数调整的描述查询从 25 条减至 1 条；不支持标签时为 0 条。
WRITE 与必要 ACK 不计入描述查询，仍然保留。

`test/rotary_test.dart` 覆盖异步等待显示、规范化实际值、失败恢复与卸载后完成。
其余现有测试覆盖手机/横屏/桌面、大字体、减少动画、视觉回归和局部重建。
完整回归共 80 项通过，`flutter analyze --no-pub` 无问题，Windows Release 已重新打包至 `APP/Apexis/`。

本次没有烧录固件或进行实机参数写入，也没有继续多效果崩溃测试。
请求数量验证不等于实机耗时测量；USB/固件自身的应用与通知耗时仍需设备恢复后实测。
