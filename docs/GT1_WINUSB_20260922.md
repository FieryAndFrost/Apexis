# GT1 Windows 私有 USB / WinUSB

## 当前状态

2026-09-22：已将 Windows 应用和 GT1 固件切换为 **UAC + 单个厂商自定义 Bulk 接口**。不保留 CDC 回退入口，也不自动尝试 Windows MIDI；旧 CDC 固件不会被新应用扫描到。历史代码和测试记录不代表当前实现。

固件和 Windows Profile 应用已构建，**已烧入 GT1 并完成 Windows 自动绑定、3,000 次读取、应用控制器同步和单参数写入/恢复验证**。音频接口正常枚举；音频实际播放/录音同时通信、复杂效果链和长期稳定性尚未验收。之前 CDC 的延迟数字不直接用于本版本。

最终应用回归：159 项 Flutter 测试全部通过，静态分析无问题；Windows Profile 可执行文件与 `apexis_usb_io.dll` 已生成。原生扫描仅找到 GT1 私有接口，没有将 DEBUG 的 COM/MIDI 接口作为应用通信端口。

初始只读检查发现 DEBUG `AC7911B8 / 010 / JLD00010` 在线，目标供电关闭、USB 路由 `disconnect`。用户确认 GT1 仅由 DEBUG 目标 USB 供电后，开启供电、备份、进入 BOOT 并烧录。最终保持目标供电 ON、路由 `pc`、无过流，未修改 DEBUG 固件。

## USB 契约

| 项目 | 值 |
| --- | --- |
| 试验 VID/PID | `3654:4E55`，与旧 CDC `3654:4B55` 分离，避免驱动缓存混用 |
| bcdUSB / bcdDevice | `0200`（Full-Speed） / `0202` |
| 音频接口 | 00–02，系统 USB Audio 驱动，未接管 |
| 控制接口 | 03，Class `FF` / Subclass `00` / Protocol `01` |
| 数据端点 | OUT `04`、IN `84`，Full-Speed Bulk，最大包 64 B |
| Windows 接口 GUID | `{F7414EE8-AF2E-489C-A4F9-16597DB74837}` |
| 自动绑定 | Microsoft OS 1.0：字符串 `EE`、vendor code `20`、兼容 ID `WINUSB`、`DeviceInterfaceGUID` |
| 会话控制 | `bmRequestType=41, bRequest=30, wIndex=3, wValue=0/1, wLength=0`，关闭/打开会话 |

PID 是沿用现有板卡 VID 下的本地试验身份；正式量产前需由厂商确认 VID/PID 分配。WinUSB 只绑定接口 03，不替换复合设备父节点或音频驱动，不要求 Zadig/自定义 INF。

应用层继续使用原 GT1 的 `F0…F7`、7-bit 编码、校验、应答、revision 和通知协议，最大帧 244 B。会话控制每次更新 generation，防止旧请求/通知串入新连接；打开后仅连接阶段排空 100 ms，不给逐次参数操作添加等待。

Windows 本轮直接调用系统 WinUSB API，经 `apexis_usb_io.dll` / Dart FFI 接入，而非引入 libusb DLL。私有线协议不依赖 Windows，未来 macOS 可用 libusb/IOUSBHost 实现同一契约；**本轮未实现 macOS 后端**。

## 实现与安全边界

- `windows/usb_io`：SetupAPI 按 GUID 枚举，再核对 VID/PID/MI；打开时重新枚举并检查设备描述符、接口类和两个 Bulk 端点。不会打开 DEBUG 或 COM 口。
- 独立 worker 负责串行化操作，独立 RX isolate 等待数据，不阻塞 Flutter UI。接收按 64 B USB 包连续交给现有协议分帧器。
- 写管道超时 250 ms，原生写入/控制额外等待上限 500 ms，Dart worker 截止 5 s；部分写入/超时不自动重发非幂等命令。
- 关闭顺序：通知 RX 取消，等待 I/O 完成及 RX isolate 退出，再关闭会话、释放 WinUSB/文件句柄。不会在驱动持有内存时释放缓冲区。
- 不调用整个设备的复位/配置切换，不改系统驱动、服务或权限策略。企业设备限制仍可能阻止安装。
- 固件保留 SDK 的 `cdc_*`/`TCFG_USB_SLAVE_CDC_ENABLE` 名称作为预编译 SDK 的挂接槽，**不代表仍提供 CDC**。线上只有一个 `FF` 接口，没有 ACM、串口 line coding、DTR 或通知端点。`MAX_INTERFACE_NUM` 不变。
- 固件继续保留 NO_BT 诊断设置、看门狗和低压保护。没有把更换 USB 传输宣称为效果链卡死修复。

固件文件位于忽略目录 `artifacts/firmware-source/gt1`：`apps/business/product_cdc.c`、`product_winusb_descriptors.h`、`apps/common/device/usb/device/user_setup.c`、`apps/hw/br27/sdk_config.h` 和 `CMakePresets.json`。这些私有固件源未因此加入公开应用仓库。

## 构建与运行

VS Code 选择 **Apexis · Windows WinUSB（性能模式）**，按 F5。Windows 的其它正常启动项也使用 WinUSB，无需 `GT1_USB_TRANSPORT` 开关。

```powershell
flutter build windows --profile
cmake -S windows/usb_io -B build/usb_io -G "Visual Studio 17 2022" -A x64 -DAPEXIS_USB_TESTS=ON
cmake --build build/usb_io --config Release
ctest --test-dir build/usb_io -C Release --output-on-failure
flutter analyze --no-pub
flutter test --no-pub
dart run tool/probe_usb_scan.dart
```

应用：`build/windows/x64/runner/Profile/apexis.exe`，需连同同目录的 `apexis_usb_io.dll`、Flutter DLL 和 data 一起使用。

固件目录内：

```powershell
cmake --preset app-debug-winusb
cmake --build --preset app-debug-winusb --parallel 8
python -B tools/package_firmware.py --build build-debug-winusb --verify
```

输出：`build-debug-winusb/flash-package/`。普通构建不下载；算法使用校验过的预编译库，不声称完成算法源码审计。
