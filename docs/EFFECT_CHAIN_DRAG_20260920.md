# 效果链拖拽排序

已移除效果参数区两个移动按钮；保留“删除效果”按钮。

## 实现

- `EffectChainEditor` 使用 Flutter 原生横向排序列表，鼠标直接拖拽，触屏长按拖拽；拖至边缘自动滚动。
- 卡片拖动与让位在本地完成；松手后经现有 `patchField(320, ...)` 版本写入与读回，仅提交一次顺序。
- growable 副本生成新顺序，不改变 UNIT 数据/编号，也不改变当前选中的效果。
- 等待期间禁止再次排序；拒绝写入后采用控制器的确认顺序。音色或效果链结构变更会取消旧拖动，避免覆盖新链。
- 按 UI/UX 技能的拖拽替代操作建议保留右键位置菜单、Alt + 左右方向键及原生语义操作，不恢复已删除的底部按钮。
- 去除卡片内部 Tooltip 浮层，避免原生拖拽重排时 OverlayPortal 在布局期间重新挂载触发布局断言；完整名称仍保留在卡片语义与选中后的参数标题中。

## 验证

`test/effect_actions_widget_test.dart` 的 12 项真实 UI 入口测试通过（模拟设备）：拒绝/回退，添加替换旁路删除，双向拖拽与 UNIT 内容不变，首尾跨位，0/1/10 个效果，取消/原位不写入，右键和键盘，先改参数后排序，外部改链取消旧拖动，边缘自动滚动。

桌面效果页已视觉检查，因按钮删除及拖拽列表布局变化更新实际 Flutter 渲染预览基线；布局测试覆盖窄屏及大字号。

完整回归 150 项通过，静态分析无问题。上述 12 项 UI 测试也通过 Windows Profile 实际构建的 `integration_test/effect_actions_profile_test.dart`（模拟设备，退出码 0）；键盘事件显式携带 PhysicalKeyboardKey，避免 Profile 模式缺少 debugName 映射导致测试框架异常。

现有硬件验证入口 `HARDWARE_UI_MOVEMENT=true` 也已改为真实拖动。历史 `actualUiMovementVerified` 按钮报告不能当成本次拖拽实机验收；新入口额外记录 `actualUiDragVerified`，未运行该入口前不声明 GT1 拖拽已实测。

## 松手后横向滚动跳动修复

- 已在旧代码复现：10 个效果、720px 窗口，先滚到 200px 再拖动第 5 个效果，确认后滚动位置跳至 0px。
- 两个原因叠加：顺序变化被误当作选中项导航触发居中；列表 Key 绑定版本/可编辑状态，确认写入后重建 ScrollPosition。
- 修复后纯排序不触发自动居中，普通确认/禁用不重建列表。仅需取消已过期的活动拖动时更换列表 Key。切换选中项、增删效果及尺寸变化仍可定位，边缘自动滚动保留。
- 按 UI/UX 通用视图稳定性规则新增 4 项逐帧测试：选中项在屏幕外或就是被拖动的效果，分别验证成功和拒绝写入；确认整个松手过程偏移不变且复用同一 ScrollPosition。原边缘滚动测试也新增松手后位置校验。
- 修复后的完整回归 154 项通过，静态分析无问题；Windows Profile 构建中全部 16 项效果交互测试通过（模拟设备），包括新增逐帧滚动位置验证。
