01 / 先实现一条完整闭环

APP 不走 BLE-MIDI。首选 AE40 私有 GATT 通道，直接传本文的控制帧；不加 MIDI 时间戳。BLE-MIDI 是独立的可选 MIDI 通道，不能混用两者封装。
438 B日常首次同步的原始参数

64 B 全局 + 374 B 当前音色。不是每次连接传 128 个音色。

47,936 B完整逻辑参数库

64 + 128 × 374。完整备份、批量浏览等明确需要时再读取；不含模型、录音或 SDK 配对信息。

  1. 连接设备，发现服务和特征，先启用 AE42 Notify，再发控制请求。
  2. 查询设备身份 09 / 01 / 22 和范围能力 09 / 01 / 40。确认 protocol、schema，不凭蓝牙名称识别版本。
  3. 发送重新同步 09 / 00 / 42 : 03。收齐同一 revision 的全局和当前音色，再发 ACK；ACK 确认同版本且 state=3 后，才开放编辑。
  4. 拖动一个音量：用范围 WRITE 写完整字段，收到终态回执后，以实际值更新 UI；其他端通过通知同步。
  5. 逐步加入切音色、UNIT 编辑、鼓机、Looper、调音器、旋钮映射；最后做备份文件和异常恢复。

界面可有临时拖动值，但“设备已生效值”只来自成功回执／完整通知。数据层区分 用户编辑 和 设备更新，收到通知不能再触发 WRITE。

保存：编辑与导入改变设备 PSRAM；正常软关机才持久化。PRESET SAVE 成功不是 Flash 写入成功。突然断电仍可能丢失未保存修改。

02 / 连接、MTU 与吞吐边界

入口对接方式承载内容
手机 APP：私有 BLEService 0000AE40-0000-1000-8000-00805F9B34FB
RX 0000AE41-0000-1000-8000-00805F9B34FB：Write Without Response
TX 0000AE42-0000-1000-8000-00805F9B34FB：Notify		原始 F0 … F7 字节流；无 BLE-MIDI 时间戳。先订阅 TX 通知。
电脑：USB MIDI通过操作系统 MIDI API 打开 GT1 MIDI 端点相同 SysEx；USB MIDI 封装交给 MIDI API。USB Audio 接口不是控制端点。
可选：BLE-MIDIService 03B80E5A-EDE8-4B33-A751-6CE34EC4C700
Characteristic 7772E5DB-3868-4112-A1A9-F2669D106BF3		标准 BLE-MIDI 封装后的 MIDI/SysEx。只用于 MIDI 客户端，不是 APP 私有 GATT 数据格式。

按 UUID 发现特征，不写死 GATT handle。广播包含 BLE-MIDI 服务及 sinco 厂商标记；不能只过滤广播中的 AE40，否则可能漏掉设备。名称可能随配置变化，应连接后查询身份。Classic A2DP 音乐连接与 BLE 控制连接是两回事。

当前 MTU 是 200，不是 247

  • 固件 BLE_ATT_LOCAL_MTU=200；协商到 200 后，单次 ATT 写入／通知载荷为 197 B。协商前使用 20 B 载荷。
  • 手机按其系统 API 报告的可写长度分片；不能直接拿 200 当载荷，更不能假定所有连接均已协商成功。设备日志 ATT payload MTU=197 打印的是载荷，不是 ATT MTU。
  • 完整控制帧最大 244 B；在 197 B 载荷下满长帧拆为 197 + 47 B。Write Without Response 的传输分片不需要逐片等待业务 ACK；保持发送顺序和系统流控，整条命令才有业务回执。
  • 设备一次整帧准入能力为 min(244, 8 × 当前 ATT 载荷)。默认 20 B 时为 160 B。范围 READ／通知会缩短原始数据量；按回执的 actual count 推进。
  • 一个 Notify 不一定是一条回复，一个写入也可能包含多条完整命令。每端点独立重组，以 F0 起、F7 止；超长、断线或重新连接时丢弃未完成帧。
吞吐优化尚未改动：可评估把本地 MTU 上限改为 247，使已协商连接的 244 B 控制帧单包发送，但必须同时验证 SDK 缓冲、手机协商及 A2DP 共存。本文不把此建议写成已实现能力，也不承诺毫秒级传输时间。

当前连接参数请求先尝试间隔 7.5～11.25 ms，备用请求 15 ms，latency=0；这些是请求值，手机可拒绝或调整。实际速度还受每连接事件可发送包数、链路数据长度、系统调度、双模共存和队列背压影响。

效率原则：首次只同步当前视图；普通编辑只传变化字段；旧业务请求串行；滑杆可以合并未发送的中间值，松手后保证最终值送达。不要为每个 BLE 分片额外插入固定延时。

03 / 帧格式与整数编码

本文命令三元组写作 component / command / selector，编号用十六进制；字段偏移、字节数、范围用十进制。方括号表示 data 内字段顺序，不包含外壳。
请求：F0 00 59 device component command selector       data… XOR F7
回复：F0 00 59 device component command selector error data… XOR F7
请求固定开销 9 B；回复固定开销 10 B。
XOR = 从 00（整帧下标 1）到最后一个 data 字节逐字节异或；
回复计算范围也包含 error。排除 F0、XOR 自己和 F7。

正常 APP 使用 device=01。固件也接受 00／7F，回复回显请求 device。除 F0、F7 外所有字节必须小于 128。单帧最小请求 9 B、最大 244 B。旧业务 data 回复最大 64 B，但范围 READ／WRITE／NOTIFY 最大完整帧可到 244 B。

类型字节数编码
u710～127。
u142b0 | (b1<<7)，0～16383。
s14214 位二补码，−8192～8191；解码 u14 ≥8192 时减 16384。
u16_73低 7 位组在前；第三字节只能 0～3。用于逻辑偏移／完整 model_ref。
u213低 7 位组在前，0～2097151；EQ 频率使用此编码，不可截断成 u14。
u32_75低 7 位组在前，第五字节只能 0～15；revision／微秒进度。JS 不要用有符号 32 位位运算拼最高位。
s8 / LE16 / s16LE1 / 2 / 2只用于解包后的原始参数库，是普通 8 位字节与小端数，不是上面的 MIDI-safe 数字编码。
字符串变长普通命令名称为 ASCII，无 NUL。参数库音色名固定 17 B：最多 16 字符 + NUL，其余填零。

参数原始字节的 pack7

每组最多 7 个原始字节：先写一个 MSB 位图，再写各字节的低 7 位。位图 bit i 是该组第 i 个原始字节的 bit7；尾组未使用的位必须为 0。

raw:     00 7F 80 FF 55 AA 01 | FE
pack7:   2C 00 7F 00 7F 55 2A 01 | 01 7E
编码长度 = N + ceil(N / 7)。每个分片独立分组，不能跨帧延续位图。

仅参数范围协议使用 pack7。旧 GT1S／GT1B 文件 CHUNK 仍采用每字节两个 nibble（高四位在前、低四位在后）；不要把这两套载荷编码混淆。

04 / 首次同步、变化通知与三端协作

设备参数库是权威来源。手机与电脑各维护镜像；旋钮、按键、MIDI、手机、电脑修改均在设备 APP 单写者入口排队。revision 是运行期库级代次：实际变化后推进，同值不推进，不能当作时间戳、Flash 代次或跨重启持久编号。

连接 / 开通知 → 查询身份与能力 → action 03 重新同步 → 收齐同代次 GLOB + 当前 PATCH → ACK 同版本并进入 state=3 → 编辑 / 接收增量 → 断线后重新同步

订阅控制：09 / 00 / 42

请求 data作用
[01]订阅／续传。正在发送不重置进度；等 ACK 时重传保留范围。仅在客户端仍保有完整镜像和接收上下文时用于恢复，不用于新客户端首次建镜像。
[00]取消本端订阅，不取消普通命令回执。
[02, revision:u32_7]确认完整接收。首次必须收齐 GLOB 和所选 PATCH 两段，不能只收完 GLOB 就 ACK。
[03]订阅并强制从头同步当前视图。首次连接、APP／电脑程序重新打开、镜像损坏或丢失进度均使用此动作；不隐式同步整库。

控制回执 data 固定 7 B：[action, state, current_revision:u32_7]。state：0未订阅／1正在同步／2等待完整 ACK／3已同步。GET 42 不是订阅状态查询，不要用它代替 SET 42。

程序重开不等于设备端断线。尤其 USB MIDI，电脑程序退出后设备可能仍保留上次订阅／增量进度。新客户端先清本地旧接收片段，发送 action 03 并核对回执，之后必须收齐新的 GLOB 和当前 PATCH；不能把旧队列尾片或一条增量误当完整快照。ACK 不是发出就算完成，需检查成功回执的 revision 及 state=3；STALE 则重新 action 03。

设备通知：09 / 7E / 42，error=0

data 偏移字段长度

11本片 raw_count:u142

  • 从 offset=range_start 开始收片；其后 offset 连续，revision、range_start、range_total 一致。收齐整段后才发布该段，不能让 UI 使用半段结构。
  • 首次是 GLOB 64 B 和当前 PATCH 374 B 两个完整范围、同一 revision/schema；GLOB[0] 的 selected 必须在 0..127 且等于 PATCH 逻辑地址对应的编号。错配不得 ACK 或开放编辑。两段都齐且一致后一起确认。以 244 B 帧预算时通常为 1 + 2 条通知，但 BLE 层可能进一步拆包，不能按固定包数判断完成。
  • 首次完成后的增量按完整声明范围接收并 ACK。切音色触发当前视图重同步；重排、模型替换等以最终参数更新界面。
  • 通知会合并变化的最小／最大地址，可能包含中间未改字节，极端可接近整库。只缓存当前视图的 APP 仍须消费完整声明范围，再 ACK；视图之外的字节可以不常驻。
  • 新修改可中止正在生成的旧代次通知，并从范围起点重发。旧帧可能已在发送队列中；不得混拼两个 revision。ACK 返回 STALE 时重新同步。
  • 断线后丢弃未完成事务、旧回执、通知片段，重新读取设备；不要自动把手机离线旧镜像覆盖设备。

建议使用一个主机请求队列；业务回执和 7E 通知先分流。不要在等待普通回复时忽略通知。参数订阅只负责可保存偏好；播放进度、调音结果、实时链接状态走各自 GET，不在 47,936 B 参数区。

05 / 范围 READ

09 / 01 / 40，无 data 时查询能力；有 data 时读取范围。

请求 data 偏移字段长度 / 限制
0expected_revision:u32_75；0 表示接受执行时版本，仅适合初次／独立读取
5logical_offset:u16_73；0～47935
8raw_count:u142；1～193，且不能越过逻辑库结尾

成功回执前 13 B 为统一头：[format=1, schema:u14, revision:u32_7, offset:u16_7, count:u14]。

  • 能力查询：只有 13 B 头，offset 字段表示总大小 47936，count 字段表示当前链路最大 raw count；后面没有原始数据。
  • 范围查询：头之后紧接 pack7(raw)。回执 count 是实际数量，允许比请求少，下一次 offset += actual_count。MTU 上限协商成功时最多 193 原始字节；默认 20 B ATT 载荷时最多 119。
  • STALE：error=8，头包含最新 revision、原请求 offset、count=0。丢弃尚未拼完的旧快照，从新 revision 重读。
  • 完整多片读取：第一片可以 expected=0，其后锁定返回的非零 revision。不能每片都用 0 然后声称数据一致。
GLOB:       [0, 64)
PATCH i:    [64 + 374*i, 64 + 374*(i+1))，i=0..127
示例 01A：  i=0，起点 64
示例 05C：  i=(5-1)*4+2=18，起点 6796
完整库：    [0, 47936)

READ 可以跨记录；WRITE 不能跨记录。这是显式编码的逻辑空间，不是设备 PSRAM 物理地址，也不是 sizeof(C struct)。

06 / 原子分包 WRITE

09 / 00 / 41。小字段一条命令即可提交；大字段按帧长分片，最后一片到齐自动提交，没有额外 BEGIN / COMMIT 往返。

请求 data 偏移字段长度 / 限制
0expected_revision:u32_75；必须是镜像的非零代次
5request_id:u142；1～16383，同一事务各片相同
7logical_offset:u16_73；整个事务起点，不随片变化
10total_raw_bytes:u142；1～374，必须完全落在一个 GLOB 或 PATCH 内
12fragment_offset:u142；相对事务起点，第一片为0
14raw_count:u142；本片1～191，不能越过total
16pack7(raw)按本片raw_count计算；最大完整请求244 B

事务按顺序追加；已收区域内字节完全相同的重复片允许，不接受空洞或内容冲突。整个 WRITE 的起点和终点必须是完整字段边界，但传输分片可以穿过一个 LE16 字段。

全设备共享一个分片写工作区，绑定来源、连接、request_id、expected_revision。有效活动空闲超时 30 秒；断线、取消、STALE 都不能把半份数据发布。上传期间设备本地操作可以继续，发生真实修改后旧 WRITE 会被拒绝，不是长时间锁住旋钮或音频。

回执：不要只看 error=0

data 偏移字段说明
0～12统一 READ 头revision、事务起点、实际回读 count
13request_id:u142 B
15state0收片中；1已提交；2已提交但静音；3已拒绝
16filled:u142 B，累计已收原始长度
18total:u142 B
20pack7(actual_raw)可为空；只包含有界回读前缀，不保证整个 WRITE
state=0：仅表示片段收到，正式参数未变化。
state=1：提交完成，同值也可成功但 revision 不变。
state=2：error仍为0，参数已提交但恢复声音失败，必须提示并重同步，不能当作未执行而重复结构操作。
  • 实际回读来自正式参数，不是请求原样回显。归一化、模式切换、BPM 联动等可能改变其他字段；通过通知或 READ 补齐。
  • 244 B 帧回执最多携带 187 原始字节前缀；缓存终态遇到后续版本变化可能 count=0，只保留结果，不伪造旧实际值。
  • STALE 回执可能只有 13 B 统一头；其他错误可以 data 为空。必须先按 error 和长度判断，不能无条件读满20 B。
  • 同一请求完全相同的重传可以命中一个有界终态缓存，不重新应用。它不是无限历史或跨连接幂等机制。新事务使用新ID；重连不重发旧请求。
  • 取消未完成写入：09 / 07 / 41 : [request_id:u14]，只允许当前所属会话，成功 data 为空；不能撤销已提交结果。

推荐使用边界：普通音量／名称／参数用范围写；选 TYPE、装模型、删除 UNIT 等优先用业务命令，避免 APP 猜测默认参数、CPU 分配和资源约束。业务命令无 revision 前置条件；若需要比较代次后原子修改，应使用范围 WRITE。

通用参数页可以直接实现的规则

  1. 读取当前 UNIT 的 TYPE 和规范参数，再查询可见数、参数名称与当前模式下的范围。值和范围均以设备为准，隐藏参数仍保留在镜像。
  2. 请求 GET21 显示标签；成功就展示设备文字，error6 则展示原始整数。名称中的换行可作为布局提示，不能把 kind 编号当成 dB／Hz，或给所有 0～100 参数统一添上百分号。
  3. 例如 Flanger（TYPE 0x0702）：Sync=0 时 Rate 范围为1～100；Sync=1 时变成0～12的节拍档位，BPM范围40～240。切换后重新读参数／范围／标签，取消尚未发送的旧 Rate 拖动值；不要自行把旧整数换算成频率。
  4. 参数页未打开时不轮询这些只读描述；当前 TYPE／模型／Mode／Sync 改变后再失效对应缓存。GLOB 与 PATCH 中已明确单位的字段按本文显示，例如 INPUT 为整数 dB，不能据此类推效果内部 Gain。

资源边界：10个UNIT是控制／音色容量，不等于10个任意重型效果都能同时运行。目前 PRODUCT_CPU1_STAGE_COUNT=3；标记“仅CPU1”的有效实例超过槽位会被拒绝，不自动降到CPU0。APP保留最后成功镜像并报告设备应用失败，不能在设备拒绝后仍显示新链已生效。

文件与日常参数同步不同。APP可先把文件当不透明二进制保存／转发，导入原文件交设备校验。文件不含Looper录音、模型／IR、鼓音源、SDK密钥或校准。

对象当前格式大小与校验

不推断支持CC0 Bank Select、CC20 UNIT11等未定义映射。普通MIDI数据没有本协议的事务回执，手机／电脑依靠参数通知或状态GET观察实际结果。

13 / 错误、重试与互斥

error（hex）含义客户端动作
00命令成功／片段成功范围WRITE另看state；Looper等动作另看运行状态。
01参数、取值或业务操作失败检查上下文／长度／有效资源／运行状态。旧业务部分忙也映射为01，不假定全部返回07。
02XOR错误修正重组和校验范围，不能绕过校验。
03帧长度错误检查data宽度、尾随数据和244 B限制。
04 / 05device不符／component不支持验证身份和命令选择。
06未实现能力／旧格式无法表示元数据标签退回原始值；EQ使用20宽格式。不要继续猜字段。
07BUSY保留未完成用户意图，退避或等当前事务结束；不丢掉最终编辑值。
08STALE丢弃旧分片候选，重同步；重新编辑时用新revision和新request_id。
09范围WRITE应用失败不当成提交成功。读取状态，必要时显式重载音色；可能停留在安全旁路／静音。
  • 先检查完整帧、XOR、长度、error，再按命令解析payload；错误回执不保证带成功格式字段。
  • 错误帧或接收队列未准入不保证有回执。建议业务超时从2秒起，结构重建／文件操作允许更长；这是客户端起始策略，不是固件时延承诺。
  • 同一端一次只等待一个普通业务请求。ATT层可按系统流控连续发送一条帧的分片；不要把“业务串行”误写成“每20/197 B都等应用回复”。
  • GET可重试；TOGGLE、INC、MOVE、DELETE、UNDO等超时先读状态，不能盲重发。范围WRITE重发必须保持原ID、revision、起点、总长及内容。
  • 控制只确认参数应用／动作准入，不承诺USB、蓝牙、鼓机、音量目标在同一个硬件采样点同时锁存。
  • XOR用于帧差错检测，revision用于并发控制；两者都不是身份认证或密码学完整性。客户端连接／配对策略另行验证。
